# "m" 菜单脚本文件解码 (j.java MenuScriptInterpreter 数据底本 — JD+10)

> 文件: jar 内 "m" (599B, dc_v1507_misc/m 与 nokia_v1011/m 同构, 头 `19 00` = 25 屏)。
> 解释器: j.java (deobf/src/j_clean.java)。数值原语: 正数=定宽读 (1=byte, 2=u8, 3=short, 4=int), 负数=-skipBytes 回退。

## 文件布局 (逆向自 j.ctor / b(int) / d())

```
[0]      u8        N = 屏数 (0x19=25)
[1..]    9×int32   头表 b[9] (按 int32 读; 字节观察为 u16 对, 疑每屏入口信息,
                   j.a() 原样转交渲染器 i.a(int[]) — 语义在 i 侧)
其后每屏记录 (由屏 id n 定位: 回退到字节 2n-1 处读起):
  -n2*2        回退定位
  u8           描述长度 L (变长头)
  回退 -L
  u8           屏型 i: 0=图标菜单列表 1=图文页 2=全屏消息 3=名字录入
                       5/6=设置组 7=条件跳转 (按 f.a(设置槽) 分支)
  u8           返回屏 g
  u8           前进屏 h
  按屏型分节:
    型2: u8 底色 + short 串id → 全屏文字
    型0: u8 图资源id, 串id; u8 软键数×[short 名串, u8 型];
         菜单项循环: u8 项id, u8 类型(4=设置循环项), u8 子项数,
                     u8 图标, 名串 short, 图标 int, u8×2 布局,
                     目标屏 u8, 设置对 e[] (short×2n)
    型1: 同头 + u8 正文串 + u8 选项数 → e[]
  尾: f.b[屏id] = 栈值 (历史), f.d(n) 记屏
```

## 屏栈语义 (j.a(int) / o() / tick)

- f.g (screenMode) 由屏型映射: 型4→1, 型5→2, 型6→3, 其余→0
- f.b[屏id] 历史 = 渲染器光标记忆 (菜单列表记住上次选中项)
- 软键按屏型由 j.e() 重注册; FIRE → c(项类型) 位分派 (见 j_clean)

## 首屏抽查 (n2=6, 字节[11]=0x04)

屏 6 = 型 4 (s=1): 与 GameMIDlet.q() case1 返回游戏屏衔接 — 即"进入游戏"动作屏。
全 25 屏的逐屏解码属数据展开, 需要时按上表程序化解析 (无未读代码, 仅数据)。
