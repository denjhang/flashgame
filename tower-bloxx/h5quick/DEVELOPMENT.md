# 都市摩天楼 J2ME 快速模式 H5 移植 — 项目开发文档

> 2026-10-02 定稿。本文记录从"Flash 版混搭移植"到"J2ME 纯血独立移植"的完整决策链、
> 技术要点与踩坑实录。工程位置：`tower-bloxx/h5quick/`（当前主线），`tower-bloxx/h5/`（旧版，冻结）。

---

## 1. 项目目标的演进（为什么推倒重来）

项目最初以 Flash 网页版《Tower Bloxx》(AS2, bz.esg.game 包) 为权威参照做 H5 复刻，
后经第 76 轮转向、2026-10-02 用户定稿：**专做 J2ME 手机版快速模式盖楼的忠实移植**。

- **唯一权威**：J2ME 版 = `House.java`（Nokia City Bloxx 2008 v1.0.12, 4420 行）+ r0 资源包
  + scene.m3g (JSR-184) + MIDI 曲库 + 中文语言包。
- Flash 版降为姊妹作参考（数值交叉验证、不移植其素材与语义）。
- City 建造模式为非目标（旧 h5 已实现部分冻结保留）。
- **禁止任何 Flash 内容混入**（旧 h5 混搭 Flash mp3/精灵/公式，是观感与手感失败的根源之一）。

旧 h5 判定为不可修复级偏差——不是缺陷清单长，而是"每轮局部有依据、全局无人负责"的增量式
开发把三套视觉语言（M3G 3D + Flash 精灵 + DOM HUD）缝在了一起，且核心公式抄错分支。
决策：另起 `h5quick/` 从零写，旧版冻结不再投入。

### 方法论教训（写进纪律）

1. **混淆代码必须先确认运行态归属再下结论**（第 77 轮曾误判"J2ME 钩可操控"即为教训）。

## 3. h5quick 架构

240×320 原生分辨率（×2 显示）。四层分离，对号 J2ME 的 2D/3D 分工：

```
┌ bg2d  (2D canvas)  程序 17 色带渐变天空 + 28 型高度带环境位图 (r0 id42-68)
├ game  (WebGL)      仅 3D: 楼块/地面/吊臂/缆 (scene.m3g → GLB), alpha 透明背景
├ hud2d (2D canvas)  全部 HUD: 命数/人口/层数/连击条/星框/落地角标 (r0 位图字模)
└ DOM    弹窗/开场 boot
```

J2ME 原版正是"3D 只清深度、2D 画一切背景"——架构同构，不是仿制。

### 3.1 玩法核心（全部按 TOWER_CORE.md 公式对号）

- **帧循环**（:1697）：25ms 门控累子, 序 = 相机→天气→飞禽→摆钩→块物理→塔摇摆→塔重建→惊慌人群→连击计时。
- **摆钩**（p:1791）：`aK=cQ·(−cosθ)`, `aL=aJ−cO−aH−cR·sinθ`, θ=200·aP/cP; 参数表
  aQ/aR/aS 按层数插值——快速局分支 **60 层到满幅**（旧 h5 错用城市分支 3 层即满幅）。
- **投放**（J:3716）：挂钩态 + **相机到位 aW==aX** 双门槛; 抛物线 `aA=aD+aC·t/256−t²/200`
  + 水平惯性 `az+=aB·dt/512`（aB=投放瞬间钩速——漂移是玩法核心, 玩家须补偿）。
- **命中**（F:2776/G:2790）：游标 dD 沿层窗口扫描（层中心 ±256）; **失配返回上个命中层**；
  分支 = 地基/顶层落住（|n3|≤127）/顶层过界（错位倾塌变体）/命中低层（计数连锁）。
- **计分连击**（y:2920）：人口 = 层数/10 + 增量; 银行 `bB+=bz·(2+层数/10·2)`;
  计时 **完美固定 6000ms, 流逝加速 `dt·(1+(bz−1)/6)`**（旧 h5 用了 Flash 公式）。
- **塔歪**（A():1999）：**不是刚体旋转**——层顶链式 +256、层心=倾斜累计逐层传导、
  顶块落地 100/500/800ms 三段缓动、每层持久倾斜 cF=±偏差/4 随机翻号。
- **惊慌人群**（t/B）：8 槽状态机, 生成 n/2 人（r0 id12/13 两帧小人, 镜像绘制）。
- **存档**（g:443/h:618）：quickModeRS 字段子集 → localStorage, 退出存/结算清。

### 3.2 渲染管线（按 n.java/House.f() 原文还原）

- **相机**：`setPerspective(55·1.2333, 0.825, 10, 10000)` — fovY 67.83°、aspect 0.825
  （**非屏比 0.75**, n.java setupViewport 的 0.7/0.3 修正式）; 位姿 `(塔x, aW, cI)` 朝 −z。
- **cI 标定**：y():1436 迭代——投影世界点 `(0,−384,128)` 至屏心下方 ≤48px, 收敛于 cI≈2128。
- **网格**：**零缩放原始坐标**（m3g bias/scale 编码已由 GLB 解码, uid13 块恰为 256³=1 层）;
  平移直传、rotZ/rotY 度数直传（b(5参):3340, 888=随机翻滚/999=屋顶特记）。
- **uid 表**（bl=4）：标准块=13、地面=9、吊臂=8、缆=7 → GLB 节点 `mesh<uid+250>`。
- **灯光**：J2ME 每帧 resetLights 后无灯 → three.js 全 MeshBasicMaterial（无光照着色）。

## 4. 踩坑实录（每条都花过真实排障时间）

| 坑 | 症状 | 根因 | 修法 |
|---|---|---|---|
| 摆幅抄错分支 | 钩子 3 层即满幅疯摆 | 用了城市模式插值公式 | 快速局分支 60 层线性 |
| F() 返回值语义 | 塔永远盖不高 | 失配应返回**上个命中层**而非 −1 | 一字之差 |
| aJ 基线不更新 | 楼长高后钩子低于塔顶, 落块砸低层连锁 | 重写渲染层时删了 z():1779 | camTick 两分支各补 `aJ=aW+1920` |
| Vector3 无 w | cI 迭代冲到 20028 封顶, 万物缩小 9 倍 | `project()` 已含透视除法, `pv.w` 恒 undefined | 直接用 ndc.y |
| 节点名错配 | 3D 全空 | GLTFLoader 拆子网格 → `mesh263`/`mesh263_1` | 查找兼容 `_N` 后缀 |
| 幽灵初速 | 首块带着 7864 假速度飞出屏 | 首摆 tick 速度基准 aO 未初始化 | swInit 门 + 完整提钩过程 |
| GLB 画布截不出 | 合成截图 3D 层空白 | WebGL rAF 后清缓冲 | preserveDrawingBuffer |

## 6. 第三轮修正记要（2026-10-02，用户验收驱动）

- 黄路颜色 0x463c14 勘误（hex 传错一位）
- 相机抖动/移动路径统一失效地平线缓存
- **dG 楼群机制精读收口**：楼高为屏像素、top=aU−h+n2s、地面只露下段、升高后顶饰（天线红灯/
  宽顶箱）入画、沉出屏底永久移除——"随楼升高看见屋顶"是原文机制。塔升高时的视觉演进：
  地面（条纹贴地平线）→ 中段（楼顶入画）→ 高空（楼沉出屏, 只剩程序天空+环境位图）
- 89 天际线=城市专属（装载/置 null 时机均已核）；塔模式背景仅 dG+程序天空
- 事故记录：一次被中断的 python 补丁把 game.js 截断为 0 字节——git checkout 恢复后重打补丁。
  教训：`open(path,'w')` 与写入之间不可被异步打断, 大补丁必须"先写临时文件再 rename"
